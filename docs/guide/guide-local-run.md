# 🚀 로컬 서버 실행과 접속 진단

## 📖 개요

참고 프로젝트와 동일하게 Python 표준 라이브러리 정적 서버를 사용한다. 포트는 참고 프로젝트 7901과 구분해 7902로 고정한다. 외부 배포나 상시 서비스 설치는 하지 않는다.

## 🧩 주요 내용

### 🚀 실행

Finder에서 프로젝트 루트의 `start.command`를 더블클릭한다. 터미널 창이 열리고 실제 포트 열기에 성공한 뒤 접속 주소를 출력한다. 창을 유지하며 종료는 Control+C로 한다.

터미널에서는 저장소 루트에서 `python3 tools/serve.py`를 실행한다. 스크립트 위치를 기준으로 루트를 찾으므로 다른 작업 디렉터리에서 절대경로로 실행해도 같은 프로젝트를 제공한다. 기본 `python3 -m http.server 7902 --bind 127.0.0.1` 방식도 계속 사용할 수 있다.

- 목록: `http://127.0.0.1:7902/apps/`
- 루트: `http://127.0.0.1:7902/`
- 실행기 상태: `http://127.0.0.1:7902/_local/health` (tools/serve.py 실행 때만 제공)
- 준비 확인: `python3 tools/serve.py --check` (포트를 열지 않고 등록 31개 진입 파일 확인)

### ✅ 오류 구분

| 현상 | 확인과 처리 |
|---|---|
| 서버 실행 전 접속 거부 | 실행기를 시작하고 성공 메시지 확인 |
| 포트 사용 중 | 같은 실행기의 health 응답이면 기존 서버 안내, 다른 프로세스면 오류 안내. 임의 종료하지 않음 |
| Operation not permitted | 실행 환경의 포트 권한 제한. 코드나 포트 변경으로 우회하지 않음. 권한이 있는 로컬 터미널에서 실행 |
| 다른 페이지 또는 404 | 실행기 사용 여부와 실제 루트·URL 확인 |
| file URL에서 모듈 실패 | 파일 더블클릭 대신 HTTP 주소 사용 |
| 앱이 안 뜸 | 브라우저 콘솔·요청 실패를 확인하고 개별 검증 기록에 재현 단계 기록 |

현재 도구 세션에서는 포트 바인딩 제한과 권한 확장 자동 거부를 확인했다. 실행 파일 준비 검사와 shell 문법 검사는 통과했지만 서버가 실행 중이거나 HTTP 접속에 성공했다고 기록하지 않는다. 맥 로컬에서 실행기를 열면 해당 환경의 실제 성공·실패 결과를 안내한다.

## 📌 요약 정보

코드 변경 없이도 기본 정적 서버로 실행할 수 있으며, start.command와 tools/serve.py는 경로·상태·오류 진단을 안정적으로 제공한다. 로컬 실행과 실제 플레이 검증은 별도 단계다.
