### 🔑 제작 원칙

- 원작을 관찰한 뒤 추상적인 목표·행동·피드백을 자체 요구사항으로 다시 쓴다. 원작 소스 코드·추출 리소스·고유 레벨 데이터·문제집·대사를 입력으로 사용하지 않는다.
- 이름·로고·캐릭터·아이콘·음악·음성·사진·일러스트·애니메이션·문구·화면 배치·시각 계층·레벨 순서와 문제는 독립 제작한다. 이름과 색만 바꾸는 방식으로 충분하다고 판단하지 않는다.
- 대표 화면과 주요 상태별로 구조·형태·이야기·상호작용 결과를 검토한다. 원작을 떠올리게 하는 고유 표현의 조합이 남으면 수정하거나 해당 요소를 제외한다. 단순한 유사도 백분율로 안전을 판정하지 않는다.
- 일반 아이디어·규칙 참고와 구체적인 표현 이용을 구분하되, 규칙이라고 부른다는 이유로 특허·상표·디자인·부정경쟁·계약상 제한까지 해결됐다고 보지 않는다.
- 원작 이름은 내부 출처와 분석에 필요한 범위에서만 언급하고, 사용자 화면·제품명·홍보에 제휴·공식 후속작·승인된 클론으로 오인하게 쓰지 않는다.
- 외부 리소스는 라이선스와 사용 범위를 파일별 확인한 뒤 도입한다. ‘무료’, 검색 결과 노출, 출처 기재만으로 사용 가능하다고 판단하지 않는다.
- AI로 제작한 그림·문구도 원작 캐릭터·작가 표현·상표를 복제하도록 요청하지 않고, 결과의 유사성·출처·도구 조건을 점검한다.
- 리뷰에는 원문 링크와 사실 중심 요약만 둔다. 원작 스크린샷·설명 전문을 저장소에 수집하지 않는다. 허용된 공식 피드의 최소 메타데이터와 조사 시각을 보존하고 제품 UI에 재배포하지 않는다.

### ✅ 완료 및 공개 기준

1. 리뷰에서 추상 규칙과 고유 표현을 분리하고, 계획에서 자체 표현과 독자 경험을 확정한다.
2. 구현 시 외부 파일·폰트·아이콘·음원·원작 코드를 가져오지 않았는지 확인하고 필요한 라이선스 자료를 보존한다.
3. 완료 전에 출처·권리 기록과 주요 화면·상태의 표현을 검토한다. 자료 확인이나 라이선스가 불명확한 요소는 제외·대체하고 기록한다.
4. 검증 기록에는 ‘자체 제작 및 출처 점검 통과’와 ‘법률 검토 미실시’를 구분한다. 출처 기재·로컬 실행·스타일 변경만으로 무침해를 선언하지 않는다.
5. 외부 공개·상용화·App Store 제출을 진행할 때는 배포 지역의 관련 권리·상표와 최신 플랫폼 정책을 다시 확인한다. 해소되지 않는 권리 쟁점은 해당 요소의 사용을 보류하고 필요 시 전문 검토를 받는다.
