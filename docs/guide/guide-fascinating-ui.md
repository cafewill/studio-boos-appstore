# ✨ Fascinating 반응형 UI 가이드

## 📖 개요

이 프로젝트의 “Fascinating”(페시네이팅)은 사용자가 제공한 스팍의 표현 맥락에서 가져온 디자인 원칙이다. 예상 밖의 발견을 만났을 때의 절제된 놀라움과 호기심을, 간결하고 직관적인 조작과 작은 반응으로 전달한다. 이 설명은 사용자 제공 맥락이며 작품 고증을 위한 자료가 아니다. 특정 캐릭터·외형·대사·브랜드를 복제하는 테마로 해석하지 않는다.

## 🧩 주요 내용

### 🔑 모든 화면에 적용할 원칙

- 브라우저 기본 INPUT·SELECT·BUTTON 외형을 그대로 나열하지 않는다. 콘텐츠의 연령·컬러·용어·놀이 맥락에 맞는 자체 시각 체계로 구성한다.
- 아이가 ‘무엇을 할 수 있는지 → 눌렀을 때 무엇이 달라지는지 → 다음에 무엇을 할지’를 자연스럽게 알 수 있게 한다. 주요 행동은 화면마다 명확히 강조한다.
- 흥미로운 발견은 결과에서 제공한다. 조작 위치·뒤로 가기·선택 규칙은 예측 가능하게 유지한다.
- 불필요한 장식과 설정을 줄이고 여백·시각 계층·짧은 문구로 내용을 정리한다. 아이 화면과 보호자 설정의 정보량을 다르게 설계한다.
- 호기심을 주는 작은 변화는 사용자의 행동에 연결한다. 반복 보상·자동 팝업·과한 반짝임·큰 소리로 주의를 붙잡지 않는다.
- [아이들용 설계](guide-child-design.md)의 정서·발달·컬러·네이밍·터치 영역·대비 기준을 함께 적용한다.

### 🌈 일관된 조작, 다양한 놀이 세계

- 코드 설계의 일관성과 화면의 획일화를 구분한다. 익숙한 도움·쉬기·기본 조작을 바탕으로, 콘텐츠마다 다른 장면과 재료를 만나게 한다.
- 소풍은 돗자리와 바구니, 분류는 수납장과 장난감, 음악은 소리 도구와 리듬 무늬처럼 목표 행동이 구체적인 세계와 이어져야 한다.
- 색·이름만 바꾸거나 같은 기하 도형을 반복하는 것을 다양한 아트로 간주하지 않는다. 각 화면은 다른 이야기·구도·대상·피드백 결과를 가진다.
- 질리지 않는 느낌은 강한 섬광·무작위 보상·강제 체류 대신 탐색·조합·변화의 발견으로 설계한다.
- MVP의 규칙 구현과 고유 장면·아트·연출 완성 상태를 구분하고 실제 화면 비교로 확인한다.

### 🧩 기본 컴포넌트를 대체하는 표현

| 기본 외형·구성 | 우선 검토할 커스텀 UI | 사용 기준 |
|---|---|---|
| 짧은 SELECT | 그림 선택 카드·라디오 타일·분할 선택 버튼 | 선택지가 적고 한눈에 비교할 수 있을 때 |
| 긴 SELECT | 검색 가능한 목록 또는 스타일을 맞춘 select | 보호자 영역 등에서 실제로 긴 목록이 필요한 경우, 복잡도와 접근성 확인 |
| 텍스트 INPUT | 먼저 그림·선택형 조작으로 목적 달성, 필요할 때 스타일을 맞춘 입력창 | 자유 입력이 실제 필요한 경우만 제공, 개인정보 수집 원칙 유지 |
| CHECKBOX·RADIO | 큰 체크 타일·선택 카드 | 선택 표시와 설명을 함께 제공, 단일/복수 선택을 구분 |
| 설정 토글 | 상태 글자가 있는 스위치 또는 두 선택 버튼 | 켜짐/꺼짐이 색 외에도 명확해야 함 |
| RANGE | 큰 손잡이·값 표시·증감 버튼이 있는 조절 UI | 드래그 외 탭·키보드 대안 제공 |
| 기본 BUTTON | 콘텐츠 테마에 맞는 주요/보조/아이콘 버튼 | 아이콘만 쓸 때도 의미·접근 가능한 이름 제공 |
| 긴 설정 폼 | 항목별 카드와 필요한 설정의 단계적 노출 | 현재 값·변경 결과·돌아가는 경로가 명확해야 함 |

선택 카드로 바꾸는 것이 항상 적합한 것은 아니다. 화면을 차지하는 공간과 선택지 수를 판단한다. 커스텀 팝업을 새로 만들 이유가 없으면 기본 요소의 외형을 다듬어 사용한다.

### 🖐 HTML 의미와 조작 보존

- 커스텀 UI는 외형과 경험을 설계한다는 뜻이다. `button`, `input`, `select`, `label`, `fieldset`, `legend` 등 적합한 HTML 의미와 기본 동작을 가능한 한 활용한다.
- 클릭 가능한 div·span으로 네이티브 기능을 대체하지 않는다. 기본 요소를 재사용할 수 없는 경우에만 역할·상태·키보드 동작을 완전하게 구현한다.
- `appearance: none`으로 기본 표시를 없앴다면 선택·체크·초점·비활성·오류 표시를 빠짐없이 재구성한다. 접근성 트리에서 실제 입력 요소를 제거하지 않는다.
- 입력창은 placeholder만으로 설명하지 않고 연결된 label을 제공한다. 적절한 입력 유형·모바일 키보드·값 검증과 짧은 오류 안내를 유지한다.
- 단일/복수 선택 상태는 의미 있는 HTML 또는 적절한 ARIA 상태로 전달한다. 키보드 초점과 선택값을 구분하고, 장식으로 포커스 표시를 숨기지 않는다.
- 커스텀 목록·팝업은 열기·선택·취소·닫기·초점 복귀·화면 밖 넘침을 처리한다. 모달에만 필요한 초점 제한을 일반 목록에 무조건 적용하지 않는다.
- 마우스 hover 없이 터치·키보드만으로 모든 핵심 기능을 사용할 수 있어야 한다.

### 📐 반응형 구성

- 작은 화면부터 설계하고 CSS Grid·Flex·유동 폭·최소/최대 크기로 확장한다. 고정 좌표와 고정 높이로 전체 UI를 맞추지 않는다.
- 모바일에서는 한 열과 큰 선택 영역, 태블릿에서는 선택과 활동의 병렬 배치, 데스크톱에서는 적절한 콘텐츠 폭과 여백을 검토한다. 픽셀 크기만 확대하지 않고 내용에 맞춰 재배치한다.
- 긴 한국어 문구·글자 확대·가로세로 회전·safe area·화면 키보드 등장에도 버튼과 현재 입력값이 가려지거나 사라지지 않게 한다.
- 화면 폭 변화로 상태를 초기화하지 않는다. 팝업·카드·설정 패널은 화면 안에 유지하고, 필수 조작을 가로 스크롤 뒤에 숨기지 않는다.
- 크기·간격·글꼴·곡률·그림자·색상·동작 시간은 CSS 변수로 역할별 관리한다. 부드러운 외형 때문에 대비나 버튼 식별성을 낮추지 않는다.

### 🖼 브랜드·문구와 첫 화면 밀도

- 공통 로고는 `apps/shared/logo.svg`와 `brand.js`에서 관리한다. 목록과 개별 활동이 같은 자체 SVG와 워드마크를 사용하며 원작 로고나 외부 아이콘을 반입하지 않는다.
- 둥근 삽화·장식은 그림 전용 컨테이너에서만 잘라낸다. 안내·상태·캡션은 그 밖의 일반 문서 흐름에 두고 절대좌표나 이미지 마스크 안에 넣지 않는다.
- 좁은 화면에서 긴 소개와 큰 삽화를 단순히 세로로 쌓지 않는다. 820px 이하에서는 큰 소개 삽화 대신 관심 선택 버튼과 실제 놀이로 연결되는 발견 카드로 바꾼다. 모바일 목록도 그림 옆에 제목·설명·시작을 배치해 탐색을 앞당긴다. 화면마다 역할과 정보 우선순위를 재설계하고 글자·그림 크기만 줄이지 않는다.
- 긴 문구·200% 확대·360/390/520/768/1280px 폭에서 가로 넘침과 캡션 잘림을 확인한다. 작은 캡션도 줄바꿈을 허용하며 고정 높이로 자르지 않는다.
- 필터는 좁은 화면에서 짧은 레이블·균등한 선택 영역으로 구성하고, 검색창은 전체 폭으로 배치한다.

### ✨ 작은 발견과 반응

| 상황 | Fascinating 경험 예시 |
|---|---|
| 모양 선택 | 선택한 조각의 윤곽이 또렷해지고 들어갈 자리와 연결되어 원리를 보여 줌 |
| 수량 활동 | 탭한 사물이 하나씩 묶이며 수와 양의 관계를 드러냄 |
| 도움 요청 | 정답을 즉시 덮어 보여 주기보다 다음에 살펴볼 부분을 조용히 강조 |
| 창작 | 아이가 고른 두 요소의 조합으로 새로운 무늬를 보여 주고 되돌리기 제공 |
| 마무리 | 이번에 발견한 내용을 짧게 보여 주고 다시 하기·쉬기를 동등하게 제공 |

피드백은 조작 직후 명확하게 전달한다. 장식 애니메이션 때문에 입력을 막거나 진행을 기다리게 하지 않는다. 움직임 줄이기 설정에서는 정적인 강조로 대체하며, 소리·진동 없이도 같은 의미를 전달한다. 예측 불가능한 보상을 반복해 접속이나 체류를 유도하지 않는다.

### ✅ 설계 기록과 검증

계획과 콘텐츠 README에는 주요 컴포넌트의 목적·외형·HTML 의미·상태·터치/키보드 동작, 모바일/태블릿/데스크톱 배치, 작은 발견을 제공하는 상호작용 1개 이상, 움직임 줄이기 대안을 기록한다. 의미 없는 효과를 채우기 위해 상호작용을 추가하지 않는다.

검증 시 기본·선택·누름·초점·비활성·오류 상태 중 해당 항목을 확인한다. 긴 문구·확대·회전·터치·키보드·스크린리더의 이름과 상태·팝업 취소와 초점 복귀를 확인하고, 실제 검사한 도구와 환경을 남긴다. ‘예쁘다’만으로 통과시키지 않고 주요 행동 식별·선택 이해·결과 이해·다음 행동의 연결을 관찰한다.
