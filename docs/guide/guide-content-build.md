# 🛠 콘텐츠 구현 가이드

## 📖 개요

독립적인 로컬 웹 콘텐츠를 구현한다. 첫 콘텐츠 `apps/shape-garden/`과 목록을 구현했으며 아래 구조를 기준으로 후속 콘텐츠를 추가한다.

## 🧩 주요 내용

### 🗂 기본 구조

```text
apps/
  catalog.js              # 전체 목록 (기존 1개 + 신규 registry)
  content-registry.js     # 신규 콘텐츠 메타데이터
  shared/                 # host · board-activity · UI · 저장 · 오디오 · 수명주기
  {slug}/
    index.html
    README.md
    src/
      main.js             # 공통 boot 호출
      activity.js         # createActivity 수명주기 계약
      model.js            # DOM 없는 규칙·초기 상태·판정·힌트
      view.js             # 상태의 화면 표현
```


[구조·유지보수 정본](guide-content-architecture.md)의 계약과 신규 추가 절차를 따른다. 검증 진입점은 `node tools/check-all.mjs`다.

슬러그는 자체 이름으로 `a-z`, `0-9`, `-`만 쓴다. 작은 콘텐츠는 파일을 줄일 수 있으나 규칙과 UI 책임은 분리한다. 공유 코드가 필요하면 범위와 의존성을 계획에 기록하며 불필요한 추상화를 먼저 만들지 않는다.

### 📐 기술 기준

| 항목 | 기준 |
|---|---|
| 기본 | HTML/CSS + Vanilla JS ES Modules, 빌드·서버 API·외부 의존 없음 |
| 표현 | 버튼·학습 UI는 DOM 우선, 연속 애니메이션은 Canvas 2D 선택 |
| 컴포넌트 | 기본 폼 외형을 테마에 맞게 재설계, HTML 의미·접근성 유지. [Fascinating UI](guide-fascinating-ui.md) 적용 |
| 화면 | 모바일 360×640부터 태블릿·데스크톱, 가로·세로 회전 및 safe area |
| 상태 | 시작 → 시범/활동 → 힌트/재시도 → 마무리 → 다시 하기/목록; 자유 놀이는 종료 흐름으로 대체 |
| 입력 | Pointer Events, 키보드 대안, 중복 탭과 취소·화면 밖 드래그 처리 |
| 애니메이션 | 필요 시 requestAnimationFrame·dt, 백그라운드에서 일시정지 |
| Canvas | DPR·리사이즈·포인터 좌표 보정, DOM 대체 조작 |
| 소리 | 첫 사용자 조작 후 활성화, 로컬 에셋 또는 자체 합성, 음소거·작은 기본 음량 |
| 저장 | `{slug}:v1:` 접두사, try/catch·JSON 손상·범위 오류 복구, 실패해도 세션 진행 |
| 기본 저장값 | 비식별 설정과 최소 진행도만, 메모리 대체 제공 |

iOS Safari의 오디오 활성화와 포커스·화면 회전을 확인한다. viewport에 확대 금지 옵션을 넣지 않고, 페이지 전체의 터치 제스처를 막지 않는다. 터치 기기에서 지원되지 않는 햅틱을 핵심 피드백으로 쓰지 않는다.

### 📖 구현 계획 템플릿

`docs/plan/{TS}-{slug}-plan.md`에 리뷰 링크, 대상 연령·전제 능력, 목표 1개, 성공 기준, 핵심 행동, 자체 문제·에셋, 포함·제외 범위, 화면 상태, 파일 구성, 저장 스키마·초기화 범위, 검증 시나리오, 미확정 항목을 작성한다. 각 요구사항에 검증 방법을 연결한다. [아이들용 설계 가이드](guide-child-design.md)의 ‘콘텐츠별 표현 설계 기록’에 따라 정서적 경험·컬러 컨셉과 색상값·대비·용어·네이밍·피드백 문구를 계획과 콘텐츠 README에 반드시 기록한다.

[Fascinating UI 가이드](guide-fascinating-ui.md)에 따라 주요 커스텀 컴포넌트·상태·HTML 의미·키보드/터치 동작·화면별 배치·절제된 발견·움직임 줄이기 대안도 기록한다.

### 🗂 목록 데이터 계약

첫 목록 구현에서는 `apps/catalog.js`의 `CONTENTS` 배열을 사용한다.

| 필드 | 내용 |
|---|---|
| `slug`, `title`, `description` | 디렉터리 이름·자체 이름·짧은 설명 |
| `category` | `game`, `education`, `creative` 중 하나 |
| `ageBand` | `3-5`, `6-8`, `9-12` 중 주 대상 하나 |
| `skills` | 수 세기·분류 등 태그 배열 |
| `goal` | 학습 또는 놀이 목표 |
| `status` | GLANCE의 상태 값 |
| `added` | 등록일 `YYYY-MM-DD` |
| `docs` | 내부 리뷰·계획·검증 문서 경로 |

플레이 링크는 `implemented` 또는 `verified`이고 실제 진입 파일이 있을 때만 제공한다. 미검증 상태는 내부 기록에서 구분한다. 사용자 화면에는 개발 명령·문서 경로·원작 브랜드를 노출하지 않는다. 원작 분석 정보는 리뷰에만 둔다.

### 🛡 독립 제작과 권리 기록

[권리 검토 가이드](guide-originality-rights.md)에 따라 계획에 추상 규칙·자체 표현·리소스 조달 방식을 적고, 콘텐츠 README에 자체/외부 리소스 및 표현 차이·유사성 검토·미확인 권리를 기록한다. 원작 소스·스크린샷·추출 에셋·레벨·문제·고유 문구를 구현 입력으로 사용하지 않는다.

### 🚀 실행과 완료

저장소 루트에서 `python3 -m http.server 7902 --bind 127.0.0.1`을 실행한다. ES Modules는 `file://`로 검증하지 않는다. 네트워크 없이란 외부 인터넷 없이 로컬 서버로 실행한다는 의미다. 실기기 LAN 테스트가 필요하면 접근 범위와 포트를 확인한 뒤 바인딩을 조정하고 종료 후 닫는다.

구현 후 README·목록·GLANCE 현황·리뷰/계획 목차를 갱신한다. [검증 가이드](guide-content-verify.md)를 수행하고 실행한 결과만 기록한다.
