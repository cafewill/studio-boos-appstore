# 🧸 아이들용 콘텐츠 설계 가이드

## 📖 개요

다음 수치는 이 프로젝트의 초기 설계 목표다. 발달 평가·교육 효과 인증·법적 준수 판정을 뜻하지 않으며 실제 관찰에 따라 조정한다.

## 🧩 주요 내용

### 🧩 연령별 기본 설계

| 연령군 | 조작과 안내 | 초기 활동 단위 |
|---|---|---|
| 만 3~5세 | 한 화면 한 과제, 탭 우선, 그림 시범, 글 읽기 불필요 | 3~5문제 또는 2~4분 후 자연스러운 마무리 |
| 만 6~8세 | 짧은 문장과 그림, 규칙 한 가지씩 추가, 힌트 | 5~8문제 또는 3~7분 |
| 만 9~12세 | 선택·계획·설명 가능한 문제, 난이도 선택 | 5~10문제 또는 5~10분 |

위 활동 시간은 강제 카운트다운으로 표시하지 않는다. 연령별로 콘텐츠를 자동 잠그지 않으며 보호자가 난이도를 고를 수 있게 한다.

### 📖 학습 설계

- 한 MVP에는 학습 목표 하나를 적는다. 예: “1~5개 사물과 수 기호를 연결한다.”
- 목표 → 아이 행동 → 정확한 피드백 → 새 예제에 적용의 연결을 설계한다.
- 오답은 감점·실패음 대신 다시 살펴볼 부분을 알려 준다. 연속 오답에는 시범·쉬운 예제·건너뛰기를 제공한다.
- 같은 위치만 외워 맞히지 않도록 배치와 예제를 바꾼다. 무작위 생성은 정답이 항상 존재하고 규칙이 일관되는지 검증한다.
- 언어 콘텐츠는 한국어 기본, 음소·글자·단어·발음을 혼동하지 않도록 검토 근거를 기록한다. 수학 콘텐츠는 답뿐 아니라 설명과 그림 수량도 대조한다.
- 음악·미술·자유 놀이는 정답을 강요하지 않는다. 작품 저장은 기본적으로 세션 내부에만 두며 파일 내보내기는 별도 범위로 정한다.
- 성공 기록을 학습 능력 진단이나 교육 효과 증명으로 표시하지 않는다.

### 🎨 정서와 발달을 고려한 컬러 컨셉

- 모든 콘텐츠는 대상 연령·활동 분위기·강조할 행동에 맞는 컬러 컨셉을 먼저 정의한다. 팔레트 선택 이유는 설계 의도로 기록하며 발달 효과로 단정하지 않는다.
- 넓은 배경은 시각적으로 부담이 적은 색으로 구성하고, 주요 조작·활동 대상에 강조색을 제한적으로 사용한다. 밝고 선명한 색도 목적에 맞게 사용할 수 있으며 파스텔만을 정답으로 정하지 않는다.
- 배경·표면·본문·주요 행동·도움·상태의 역할을 나눠 색을 지정한다. 연한 배경에는 충분히 진한 글자와 경계를 사용하며 실제 조합의 대비를 측정한다.
- 프로젝트 검증 기준은 일반 텍스트 대비 4.5:1 이상, 큰 텍스트와 주요 조작 경계·필수 도형 대비 3:1 이상이다. 대비 수치 충족만으로 전체 접근성 검증을 대신하지 않는다.
- 고채도 색의 넓은 병치, 반복 점멸, 화면 전체의 급격한 색 전환을 피한다. 강조는 크기·여백·모양과 함께 표현한다.
- 감정은 좋음·나쁨으로 나누지 않는다. 슬픔·화남·두려움도 표현하고 이해할 수 있도록 구성하며, 특정 감정에 한 가지 색을 강제하거나 색 선택으로 아이의 심리를 판정하지 않는다.
- 분홍/파랑을 성별 선택으로 고정하거나 피부색·문화·장애를 선악·능력과 연결하지 않는다. 색 취향과 감각적 선호의 차이를 허용한다.
- 초기 컨셉 예: ‘햇살 정원’은 크림 배경·짙은 잎색 글자·살구 강조, ‘바다 탐험’은 옅은 모래색 배경·짙은 바다색 글자·청록 강조로 제안할 수 있다. 실제 색상값은 콘텐츠별 대비 검증 후 확정한다.

### 💬 용어·네이밍·정서적 피드백

- 화면 이름·활동명·캐릭터명은 아이가 발음하고 뜻을 짐작하기 쉬운 자체 이름으로 정한다. 저연령은 구체적인 사물·행동을 우선하고, 고연령은 유아적으로 느껴지지 않는 표현을 선택한다.
- 프로젝트·폴더 식별자와 아이에게 보이는 이름을 분리한다. 기술 용어·영문 슬러그를 그대로 안내 문구로 쓰지 않는다.
- 이름은 실제 놀이와 연결한다. 예: `shape-garden` → ‘모양 정원’, `counting-picnic` → ‘하나둘 소풍’. 원작 상표와 혼동되는 표현은 피한다.
- 호기심·돌봄·공감·협동·자기표현을 지원하는 이야기와 활동을 설계하되, 특정 감정을 강요하거나 순종을 보상의 조건으로 삼지 않는다.
- 아이의 능력·인격을 평가하는 ‘천재’, ‘바보’, ‘착한 아이만’, 비교·낙인·위협·죄책감을 유발하는 문구를 쓰지 않는다. ‘두뇌 발달 보장’ 같은 근거 없는 효과 표현도 쓰지 않는다.
- 결과보다 행동과 탐색을 구체적으로 설명한다. 정답이 없는 창작에 우열을 매기지 않으며 칭찬 문구를 과도하게 반복하지 않는다.
- 안내는 한 번에 한 행동을 짧게 제시한다. 유아어·어려운 외래어·비꼼·부정의 중첩을 피하고, 그림과 문구의 의미를 맞춘다.

| 상황 | 피할 표현 | 사용할 표현 예시 |
|---|---|---|
| 오답 | 틀렸어! 이것도 몰라? | 같은 모양을 다시 찾아볼까? |
| 성공 | 넌 천재야! 친구보다 잘해! | 모서리가 세 개인 모양을 찾았네. |
| 난이도 | 바보 / 천재 | 처음 해보기 / 더 도전하기 |
| 종료 | 지금 가면 친구가 슬퍼해 | 여기까지 했네. 쉬었다가 또 만나! |
| 감정 활동 | 화내면 나쁜 아이야 | 화가 났구나. 어떤 마음인지 표현해 볼까? |

### 📖 콘텐츠별 표현 설계 기록

구현 계획과 콘텐츠 README에 다음 내용을 기록한다. 원작 표현을 그대로 따르지 않고 아이에게 적합한 자체 표현을 선택한 이유를 남긴다.

| 항목 | 기록할 내용 |
|---|---|
| 정서적 경험 | 호기심·공감·협동·자기표현 등 지원하려는 경험과 이를 제공하는 실제 행동 |
| 컬러 컨셉 | 컨셉명·색상값·역할·선택 이유·텍스트/경계 대비 결과·색 외 구분 |
| 용어·네이밍 | 화면 이름·활동명·캐릭터명·핵심 용어와 대상 연령에 맞춘 이유 |
| 피드백 문구 | 시작·힌트·오답·성공·종료의 실제 문구 |
| 검토 결과 | 과자극·낙인·비교·고정관념·정서 압박 여부, 수정 사항과 미검증 항목 |

### ✨ 직관적 UI와 발견의 경험

기본 폼 외형에 의존하지 않고 대상 연령과 활동에 맞는 간결한 커스텀 UI를 구성한다. 절제된 놀라움과 호기심을 주는 상호작용·반응형 배치·HTML 의미 보존의 상세 기준은 [Fascinating UI 가이드](guide-fascinating-ui.md)를 따른다. 정서적 편안함·이해 가능성·쉬기와 종료의 선택을 함께 검토한다.

### 🖐 조작·접근성

- 주요 터치 영역 목표는 최소 48×48 CSS px, 어린 연령군은 56×56 이상으로 하고 인접 버튼 간 여백을 둔다.
- 드래그 활동은 선택 후 목적지 탭 대안을 제공한다. 손가락에 목표가 가려지는지 확인한다.
- 색만으로 정답·그룹을 구분하지 않고 모양·무늬·텍스트를 함께 제공한다.
- 소리를 끈 상태에서도 핵심 과제를 수행할 수 있어야 한다. 텍스트 없는 연령군은 그림·시범으로 안내한다.
- 버튼은 DOM의 `button`을 우선 사용하고 키보드·초점·이름을 제공한다. Canvas 활동도 DOM 설명과 대체 조작을 제공한다.
- 페이지 확대를 막지 않는다. `touch-action: none`은 필요한 조작 영역에만 한정하고, 움직임 줄이기 설정을 반영한다.
- 큰 섬광·갑작스러운 큰 소리·과도한 흔들림을 피하고 재생·음량·음소거를 제공한다.

### 🛡 개인정보와 보호자 영역

- 이름·생년월일·이메일·사진·음성·위치 등을 묻지 않는다. 입력은 그림 선택과 콘텐츠 조작을 기본으로 한다.
- 계정·분석 SDK·광고·결제·소셜·채팅·외부 전송·외부 폰트·CDN을 기본 범위에서 제외한다.
- 로컬 저장은 음량·난이도·완료 단계 등 최소값만 쓴다. 기기 공유를 고려해 개인별 프로필·아이 식별자를 만들지 않는다.
- 기록 초기화는 보호자 영역에서 대상 범위를 표시하고 확인 후 처리한다. 다른 콘텐츠나 문서 설정 키는 삭제하지 않는다.
- 보호자 영역에는 소리·난이도·저장 초기화를 둔다. 아이 동선과 분리하고 읽기 안내 등 의도적인 진입 동작을 둔다. 이것을 인증이나 보안 통제로 설명하지 않는다.
- 그만하기·목록으로·일시정지는 항상 찾기 쉬워야 한다. 쉬기 제안을 무시했다고 불이익을 주지 않는다.
- 보호자 영역은 향후 외부 링크·결제·개인정보 처리에 대한 포괄적 허용이 아니다. 이런 기능은 별도 설계 범위다.
