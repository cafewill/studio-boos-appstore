# 🧱 콘텐츠 구조와 유지보수

## 📖 개요

31개 콘텐츠를 같은 실행·저장·설정 계약으로 관리한다. 공통 기능은 shared 한 곳에서, 각 놀이의 규칙과 그림은 개별 콘텐츠에서 관리한다. 빌드 없는 Vanilla JavaScript ES Modules를 유지한다.

## 🧩 주요 내용

### 🗂 책임과 의존 방향

| 계층 | 책임 |
|---|---|
| catalog / content-registry | 메타데이터의 정본. 신규 30개와 기존 1개를 결합. 원작 브랜드 정보는 포함하지 않음 |
| shared/host | 시작·진행 번호·다음·도움·되돌리기·건너뛰기·쉬기·보호자·완료·설정·저장 |
| shared/board-activity | 모델·뷰 연결, 이력·복원·힌트 윤곽·입력 수명주기 |
| shared/storage·audio·lifecycle | 범위가 정해진 저장, 소리·백그라운드 정리, 이벤트·정리 함수 소유권 |
| shared/board-ui·garden-art | 공통 SVG·UI 표현. 특정 콘텐츠의 규칙을 포함하지 않음 |
| 개별 src/model.js | DOM 없는 createState(seed)·reduce(state,action)·hint(state). 활동별 목표·판정 |
| 개별 src/view.js | 상태를 접근 가능한 버튼·SVG로 표현하는 render(state) |
| 개별 src/activity.js·main.js | 표준 어댑터 createActivity와 공통 boot 호출 |

콘텐츠 → 자신의 모듈/공통 모듈만 허용한다. 목록 → 공통 그림 모듈만 사용한다. shared → 콘텐츠 내부 import는 금지하며, host가 catalog의 메타데이터를 조회하는 의존만 예외로 허용한다. 순환 의존을 금지한다. 의도적인 예외는 문서·검사에 이유와 검증을 남긴다.

### 🔄 실행 계약

createActivity(context)는 mount(root)·pause()·resume()·serialize()·destroy()와 현재 공통 조작용 help()·undo()를 제공한다. mount는 현재 활동에 한 번 호출하고, 재시작·단계 전환에서는 destroy 뒤 새 인스턴스를 만든다. destroy 반복 호출은 안전해야 한다.

context에는 seed, 복원 actions, prefs, 범위가 정해진 audio, announce, save, changed를 제공한다. 콘텐츠는 localStorage나 공통 dialog를 직접 조작하지 않는다. 모델은 전달받은 상태를 변경하지 않고 새 상태 또는 기존 상태를 반환하며, done boolean으로 완료를 알려준다. view는 판정이나 저장을 하지 않는다.

표준 조작은 type과 정수 id다. 허용 type은 tap·select·tool·finish·start·clear·mark·reveal이며, 복원 시 type·id 범위를 검사한 뒤 모델이 의미를 다시 검증한다. 지원하지 않는 조작은 상태를 바꾸지 않는다. 새로운 조작 종류는 검증기와 공통 계약을 함께 변경한다.

### 🛡 저장·복원·호환성

키는 {slug}:v1:preferences와 {slug}:v1:progress다. 소리는 기본 꺼짐이다. 진행은 seed·level·actions를 저장하고 현재 규칙으로 다시 실행해 복원한다. 인격·생년월일·사용자 식별자·클릭 시각·계정은 저장하지 않는다.

- JSON 손상·범위 오류는 기본값으로 복구하고 다른 콘텐츠의 키를 지우지 않는다.
- 저장이 막히면 메모리로 동작한다. 읽기만 가능하고 삭제가 막힌 환경에서는 새로고침 시 기존 값이 돌아올 수 있다.
- 이력이 512개를 넘으면 해당 진행의 영구 저장을 지우고 현재 세션으로 계속한다. 화면 접근성 알림으로 안내한다.
- 모양 정원 초기 v1의 seed·results는 완료 단계 번호로 변환한다. sound·choices 2/3 설정과 같은 키를 유지하며 공통 보호자 설정으로 조절한다.
- 모델의 조작 의미를 바꾸면 기존 replay가 달라질 수 있다. 이때는 저장 버전을 올리고 이전 진행의 변환 또는 안전한 초기화 방식을 계획·README에 기록한다. v1 내용을 조용히 바꾸지 않는다.

### 🎨 공통 계약과 고유 표현의 경계

공통화하는 것은 저장·규칙 API·수명주기·기본 조작·접근성과 내비게이션이다. board-ui는 선택 가능한 표현 도구이며 모든 활동에 같은 카드·격자·아이콘·배경을 쓰도록 강제하지 않는다. view와 콘텐츠별 스타일·아트는 독립적인 설계 영역이다.

| 공통으로 유지 | 콘텐츠별로 다르게 설계 |
|---|---|
| 도움·쉬기·목록·소리 위치와 의미 | 이야기·세계·등장 대상·재료 |
| 선택·확인·취소·키보드·초점의 예측 가능성 | 주 활동의 공간 구성·보드·도구 표현 |
| 모델·저장·상태·수명주기 API | 그림의 형태·질감·소리·발견의 결과 |
| 감점 압박 없는 피드백·종료 선택 | 반응의 맥락·문구·완료 장면 |

이름과 색만 바꾼 같은 타일 화면은 고유 표현을 완성한 것으로 보지 않는다. 목록·시작·활동·완료의 시각적 차별화와 실제 놀이 규칙 완성도는 별도 검토한다. 첫 30개는 핵심 규칙 MVP이며 모든 콘텐츠의 고유 아트와 연출까지 완성한 것으로 표시하지 않는다.

콘텐츠 스타일은 해당 폴더에 두고 `[data-app="slug"]` 아래로 한정한다. 공통 CSS에 개별 놀이의 테마와 장면 규칙을 계속 추가하지 않는다. 공통 플랫폼을 바꾸지 않고 view·아트를 바꿀 수 있어야 한다.

### 🎨 UI와 수명주기

공통 버튼·글자·색·초점·대비·반응형은 site.css와 shared/host.css가 관리한다. 콘텐츠별 배치는 view에서 공통 표현 클래스를 사용한다. 추가 CSS가 필요하면 해당 data-app 루트 아래로 제한하고 전역 요소 선택자를 추가하지 않는다.

활동마다 다른 규칙·그림·보드를 유지한다. 객관식·퍼즐·창작을 만능 퀴즈로 바꾸지 않는다. Pointer/키보드 조작은 DOM button과 선택 후 목적지 탭을 기본으로 하며, 드래그를 필수로 요구하지 않는다. 음원은 자체 합성만 사용하고 소리 없이 같은 활동이 가능해야 한다. 버튼·방향·완료는 색 외에 글·모양으로 전달한다.

이벤트는 AbortController로 소유하고 화면 전환 때 해제한다. 타이머·애니메이션·오디오는 pause/destroy 때 정리한다. 비동기 오디오 활성화가 일시정지 뒤 늦게 완료되더라도 재생되지 않도록 취소 세대를 확인한다.

### 🛠 신규 콘텐츠 추가

`python3 tools/create-content.py example-garden --title '예시 정원' --dry-run`으로 파일 목록을 확인한다. dry-run을 빼면 미등록 초안만 만들며 기존 폴더는 덮어쓰지 않는다. 생성한 초안은 규칙을 작성하기 전에는 실행·구현 완료가 아니다.

1. 목표·연령·권리·핵심 행동을 리뷰와 계획에 작성한다.
2. 모델·판정·힌트와 뷰를 독립 작성한다. createState·reduce·hint 계약을 사용한다.
3. 메타데이터를 registry에 추가하고 README·리뷰·계획·검증 경로를 연결한다.
4. `node tools/check-all.mjs`와 로컬 브라우저 확인을 수행한다.
5. 기본 파일만 생긴 초안·빈 화면·이름만 바뀐 활동을 implemented로 등록하지 않는다.

verify-architecture는 등록 31개, 필수 파일·문서, 메타데이터, 공통 어댑터 사용, 콘텐츠 간 import·순환 의존·직접 저장·외부 요청 참조를 검사한다. 모델 검사는 여러 시드의 완료 경로·입력 불변성·이력 복원과 뷰 문자열을 확인한다. 독립 규칙 검사는 스도쿠 유일해·합계·경로·고리 조건 등을 추가 확인한다.
